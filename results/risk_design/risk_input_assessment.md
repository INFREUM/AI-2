# RiskScore 입력 설계 검토

이 문서는 RiskScore 계산식, 가중치, 위험도 임계값을 정의하지 않는다. D1/D2/D3는 손상 유형이며 위험도 순서가 아니다.

## A. 정상 기준 대비 진동 변화량

- 활용 가능한 입력: 22개 진동 Feature의 절대 차이와 상대 변화율, 기준 상태, 기준 실험/Window 수.
- 장점: 측정값의 방향과 단위를 보존하며, 하중조건 일치 기준과 연결된다.
- 한계: 현재 모든 조건이 `INSUFFICIENT_EXPERIMENTS`이며 더미 Train NORMAL 기준이다. NORMAL 비교는 동일 기준 구성 데이터이므로 독립 검증이 아니다.
- 정규화: Feature 단위와 크기가 다르므로 향후 물리적 허용범위 또는 충분한 정상 반복실험 기반의 정규화 정책이 필요하다.
- HW 주의사항: 센서 교정, 단위, 타임스탬프, 하중위치, 온도, 결측 처리, 조건 미존재 시 행동을 운영 규격으로 확정해야 한다.

## B. XGBoost 구조 상태 예측 확률

- 활용 가능한 입력: Model C의 `NORMAL/D1/D2/D3` 순서 확률과 최대 확률.
- 장점: 손상 유형 가설의 불확실성을 보존한다.
- 한계: 확률은 분류 신뢰도이며 위험 심각도가 아니다. 현재 데이터는 시뮬레이션 더미이며 Window 상관성과 분할 규모가 작다.
- 정규화: 확률 자체는 0~1이지만, 실제 HW 적용 전 calibration 검증이 필요하다.
- HW 주의사항: Model C만 사용하고 환경 Feature shortcut을 RiskScore 근거로 혼합하지 않는다. 분류 확률을 D1/D2/D3 위험 순위로 해석하지 않는다.

## C. AI① 이상 탐지 결과

- 활용 가능한 입력: `anomaly_score`, `decision_ratio`, `raw_prediction`, `prediction`, 센서별 score/state.
- 장점: AI①은 동일 하중조건의 정상과 비교한 이상 정도를 제공한다. `decision_ratio`는 문서상 1 초과가 이상이며 교량 간 비교 목적이 명시되어 있다.
- 한계: AI① 더미 데이터이며 AI① 학습 실험은 AI② 후보에서 제외됐다. `prediction`은 최근 Window 지속성 규칙의 결과라 독립 점수가 아니다.
- 정규화: `anomaly_score`와 `decision_ratio`의 범위와 기준이 다르므로 공통 가중 합산 전에 측정 단위와 시간 집계 규칙을 확정해야 한다.
- HW 주의사항: AI① JSON에 점수 정의, threshold, 모델/센서 버전, 기준 조건, 생성 시각을 함께 전달해야 한다.

## 필수 선행 확인

1. 조건별 독립 NORMAL 반복실험을 확보하고 baseline 상태를 `SUFFICIENT`으로 개선한다.
2. 실제 HW에서 온도·하중·손상 유형이 독립적으로 변하는 검증 데이터를 확보한다.
3. 실험 단위와 연속 Window 단위의 집계 규칙을 정한다.
4. RiskScore의 사용 목적, 허용 오경보/미탐, 사람 검토 절차를 합의한 후에만 가중치와 단계 기준을 설계한다.
